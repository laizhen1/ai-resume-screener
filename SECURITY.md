# Security policy

## Supported versions

Security fixes are applied to the latest release.

## Reporting a vulnerability

Use GitHub private vulnerability reporting when enabled, or contact the repository owner privately. Do not open a public issue for a vulnerability that may expose resume content or allow arbitrary file processing.

Include reproduction steps using synthetic data only. Do not attach real resumes, credentials or personal information.

## Deployment note

The project is a learning foundation and has not undergone a professional security audit. Public deployments should add authentication, rate limits, malware scanning, strict proxy limits, TLS and hardened logging before accepting documents.
